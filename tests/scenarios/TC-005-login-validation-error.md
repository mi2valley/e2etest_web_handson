# TC-005 ログイン入力バリデーション（異常系）

## 目的

ログイン画面の入力チェック（必須入力・メールアドレス形式）が機能し、不正な入力ではログインできないことを確認します。

## 事前条件

- アプリが `http://localhost:3000` で起動している
- 未ログイン状態である（`launch` でセッションをリセットする）
- この手順書単体で開始し、他シナリオの実施結果を前提にしない
- **各ケースの開始前に、メールアドレス・パスワード欄の値をクリアする**（前ケースの入力が残っていると別ケースになるため）

## 画面操作

### ケース1: メールアドレス・パスワードともに未入力

1. ブラウザで `http://localhost:3000` を開く
2. 何も入力せずに「ログイン」ボタンをクリックする
3. 表示されたエラーメッセージと URL を確認する

### ケース2: メールアドレスの形式が不正

1. 入力欄をクリアする
2. 「メールアドレス」入力欄に `test@example` と入力する（ドメインのドットなし）
3. 「パスワード」入力欄に `password123` と入力する
4. 「ログイン」ボタンをクリックする
5. 表示されたエラーメッセージと URL を確認する

### ケース3: パスワードのみ未入力

1. 入力欄をクリアする
2. 「メールアドレス」入力欄に `test@example.com` と入力する
3. 「パスワード」入力欄は空のままにする
4. 「ログイン」ボタンをクリックする
5. 表示されたエラーメッセージと URL を確認する

## 期待結果

### ケースごとのエラーメッセージ

| ケース | 入力値                              | 表示されるエラーメッセージ                                             |
| ------ | ----------------------------------- | ---------------------------------------------------------------------- |
| 1      | メール: 空 / パスワード: 空         | `メールアドレスを入力してください` と `パスワードを入力してください` の **2件** |
| 2      | メール: `test@example` / `password123` | `正しいメールアドレスを入力してください` の **1件**                     |
| 3      | メール: `test@example.com` / パスワード: 空 | `パスワードを入力してください` の **1件**                          |

### 全ケース共通

- 画面は `/login`（ログイン画面）のままであり、`/cards` に遷移しない
- ナビゲーションバー（`カード一覧` / `利用明細` / `ポイント交換` / `プロフィール`）は表示されない
- 認証エラー `メールアドレスまたはパスワードが違います` は表示されない
  - 入力チェックで弾かれるため、認証処理自体が実行されない

## 補足

- エラーメッセージは `role="alert"` の要素として描画されるため、アクセシビリティツリー上で確認できる
- ログインフォームは `noValidate` 指定のため、ブラウザ標準の入力検証は動作せず、**アプリ側のエラーメッセージ**が表示される

## 合格/不合格判定基準

- **合格**:
  - ケース1〜3 で上表のエラーメッセージが表示される
  - いずれのケースでも `/login` に留まり、カード一覧へ遷移しない
- **不合格**:
  - エラーメッセージが表示されない、または文言が異なる
  - 不正な入力にもかかわらず `/cards` へ遷移してしまう
  - ケース1でエラーが1件しか表示されない（片方の必須チェックが欠落）
