# TC-006 ポイント交換の入力バリデーション（異常系）

## 目的

ポイント交換画面で不正な入力値（未入力・下限未満・保有ポイント超過）を指定した場合に、**交換が実行されない**ことを確認します。あわせて、数値以外の文字がそもそも入力できないことを確認します。

## 事前条件

- アプリが `http://localhost:3000` で起動している
- 未ログイン状態から開始する（`launch` でセッションをリセットする）
- この手順書単体で開始し、他シナリオの実施結果を前提にしない
- ポイント残高の初期値: **3,200 ポイント**
- 交換の下限: **100 ポイント**
- 「交換ポイント数」入力欄は数値入力欄（`type="number"`）であり、**アルファベットなどの数値以外の文字は入力できない**
- **各ケースの開始前に「交換ポイント数」入力欄をクリアする**

## 画面操作

### 1. ログイン → ポイント交換画面

1. ブラウザで `http://localhost:3000` を開く
2. `test@example.com` / `password123` でログインする
3. ナビゲーションの「ポイント交換」をクリックする
4. 保有ポイントが `3,200` であることを確認する

### 2. ケース1: 未入力のまま交換

1. 「交換ポイント数」入力欄が空であることを確認する
2. 「交換する」ボタンをクリックする
3. エラー表示・確認ダイアログの有無・保有ポイントを確認する

### 3. ケース2: 数値以外は入力できないこと（入力ガード）

1. 入力欄をクリアする
2. 「交換ポイント数」入力欄に `abc` と入力を試みる
3. **入力欄の値が空のままであること**（`abc` が入っていないこと）を確認する
4. そのまま「交換する」ボタンをクリックする
5. エラー表示・確認ダイアログの有無・保有ポイントを確認する

### 4. ケース3: 下限未満（100ポイント未満）

1. 入力欄をクリアする
2. 「交換ポイント数」入力欄に `50` と入力する
3. 「交換する」ボタンをクリックする
4. 確認ダイアログの有無・保有ポイントを確認する

### 5. ケース4: 保有ポイント超過

1. 入力欄をクリアする
2. 「交換ポイント数」入力欄に `5000` と入力する（保有 3,200 を超える値）
3. 「交換する」ボタンをクリックする
4. 確認ダイアログの有無・保有ポイントを確認する

## 期待結果

### ケースごとの期待

| ケース | 入力値                       | 入力欄の値       | アプリのエラーメッセージ                       | 確認ダイアログ | 保有ポイント   |
| ------ | ---------------------------- | ---------------- | ---------------------------------------------- | -------------- | -------------- |
| 1      | 空欄                         | 空               | `交換ポイント数を入力してください` が表示される | 表示されない   | `3,200` のまま |
| 2      | `abc`（入力を試みる）        | **空のまま**     | `交換ポイント数を入力してください` が表示される | 表示されない   | `3,200` のまま |
| 3      | `50`                         | `50`             | 表示されない場合がある（下記「補足」参照）     | 表示されない   | `3,200` のまま |
| 4      | `5000`                       | `5000`           | 表示されない場合がある（下記「補足」参照）     | 表示されない   | `3,200` のまま |

### ケース2 の補足説明

- 数値入力欄のため、`abc` はキー入力しても文字が入らず、入力欄は空のままとなる
- したがってケース2は「未入力」と同じ状態で送信され、ケース1と同じエラーメッセージになる
- **入力欄に `abc` がそのまま表示された場合は不合格**（数値以外を受け付けてしまっている）

### 全ケース共通

- 確認ダイアログ（`確認` / `〜ポイントを交換します。よろしいですか？`）が表示されない
- 完了メッセージ `交換が完了しました` が表示されない
- 保有ポイントが `3,200` から変化しない
- 画面は `/points`（ポイント交換）のままである

## 補足（実装上の既知挙動 — 判定時の注意）

- 「交換ポイント数」入力欄は `type="number"` に `min="100"` / `max="3200"`（保有ポイント）が指定されており、フォームに `noValidate` が無い。そのためケース3・4は **ブラウザ標準の入力検証で送信自体がブロックされ**、アプリ側のエラーメッセージ（`100ポイント以上から交換できます` / `保有ポイントを超えています`）は画面に現れないことがある
  - Chrome（日本語）での標準検証メッセージ（参考）: ケース3 `値は 100 以上にする必要があります。` / ケース4 `値は 3200 以下にする必要があります。`
  - この標準検証メッセージはネイティブのポップアップのため、アクセシビリティツリーには現れない
- 送信がブロックされた場合は画面が再描画されないため、**直前のケースで表示されたエラーメッセージがそのまま残る**ことがある。エラーメッセージの有無だけで判定せず、**確認ダイアログが開かないこと・保有ポイントが `3,200` のままであること** を主たる判定基準とすること
- 数値入力欄でも `-`（マイナス）や `e` など一部の記号は入力できるが、その場合もケース3と同様にブラウザ標準検証でブロックされる（本シナリオの対象外）

## 合格/不合格判定基準

- **合格**:
  - ケース2 で入力欄に `abc` が入らず、空のままである
  - ケース1〜4 のいずれでも確認ダイアログが表示されない
  - ケース1〜4 のいずれでも `交換が完了しました` が表示されない
  - 全ケース終了時点で保有ポイントが `3,200` のままである
  - ケース1・2 で `交換ポイント数を入力してください` が表示される
- **不合格**:
  - ケース2 で入力欄に `abc` が入力できてしまう
  - 不正な入力にもかかわらず確認ダイアログが開く
  - 不正な入力で交換が完了し、保有ポイントが減少する
  - 保有ポイントを超える値（`5000`）が交換でき、残高がマイナスになる
  - 保有ポイントが増加する（例: `3,700` — 加算バグ）
